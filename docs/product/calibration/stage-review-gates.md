# 阶段性独立审核门禁
L1研究执行规范增量；依据 ADS 4.19.0 和用户提出的阶段审核要求。D20为采纳的工程执行安排，不代表用户批准19域或内容事实。小增量仍可 recommended + 明确SKIP；一旦形成完整专业模块/阶段候选，review:required，冻结实际审核对象并按Exact HEAD执行。不得在审核前合入要求审核的stage candidate PR；若前序小增量已集成，使用覆盖完整基线与增量的阶段收口PR，明确审查累计范围。
| Gate | 阶段对象 | 独立审核完成条件 | 阻塞范围 |
|---|---|---|---|
| G01 | 领域分类、职责及迁移方案（19域为候选） | 专业范围、替代划分、owner、D3/D4迁移设计及案例/CQ/七能力影响；明确剩余缺口，不提前分配ID | 新正式D1编号、迁移及以分类为权威的建设 |
| G02 | K01专业深度示范 | 完整模块的去重、语义归属、逐知识来源条件、正反向案例、七能力、CQ与检索、未证知识隔离；验证跨来源冲突及可计算反例 | 将K01方法作为其他域正式建设标准 |
| G03 | 后续每个完整专业子域（或边界明确的紧耦合模块） | 同G02，审查相应专业对象及跨域边界；不得按条目数通过 | 相应模块关闭与依赖它的冻结任务 |
| G04 | 全域校准CAL01–06及本体复用 | 全域覆盖、关系/owner、来源、迁移、能力、CQ、案例及LLM发现性，核对已审模块和变更失效 | CAL07/T03准备 |
| G05 | L1冻结T03 | 全域研究验收、开放风险与限制、完成范围、exact SHA；仍无accepted claim数据及运行宣称 | L2及下游填充 |
| G06 | L2语义合同与试点 | 设计/约束/反例、验证方法、检索答案隔离、可执行验证，独立审核通过 | 正式知识填充 |
| G07 | 正式知识批次及最终集成 | 专业内容、源与权利、真实验证、独立评估及综合验收，依既有计划 | 批次准入、发布 |

## 审核协议
- Builder完成阶段候选、结构检查及证据清单，写入任务Issue和PR；标明review:required，review_base（累计审查起点）、exact_head、实际文件/范围、验证与限制。阶段未完成则记录OPEN，不提前派整模块验收。小增量允许继续无依赖研究但不得越过相应阻塞范围。
- 独立Reviewer在另一ChatGPT Web会话/其他agent/人类独立上下文运行；GitHub为唯一事实源，声明不同operator_id/session_ref，同transport账号允许；不能由Builder自己作独立Reviewer。按ADS先读取固定revision、任务合同及Exact HEAD，主动寻找错误与遗漏，复核原始来源和反例；不能只复述Builder统计。
- 结论PASS/ACCEPT_SCOPED（仅限完整声明范围且无未修P0/P1、符合required gate PASS语义）或FAIL/BLOCKED；P0/P1修复后exact-head复审，P2逐条记录责任/影响与延后条件，不用P2掩盖阻断；审核所依据的HEAD变动则验证影响并按ADS重新取得有效Review。旧结论不能自动适用新版本。
- 结果写回对应Issue与PR，注明exact SHA、证据、发现、判断、实际未验证项和身份；Builder随后核验记录再合并/关闭。没有独立审核不能标PASS。L1模块审核不代表L1整体冻结、正式知识填充或真实LLM实验。
- 暂以Issue/PR明确依赖和状态，连接器尚不能写native DAG依赖，不声称冻结DAG。
