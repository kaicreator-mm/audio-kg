# 案例知识与案例库建设计划（L1 草案）

状态 DRAFT；Issue #3。案例不是简单的知识例句，也不是只用 CQ 代替真实专业任务。案例用于连接跨域知识、七类能力、问题、条件、决策、操作及结果。以下均为候选，尚未执行或核实真实结果。

## 类型与证据
1. 教学示例：解释一个专业主题，允许最小合成素材。
2. 计算/推导：明确输入、假设、预期结果及推导，例如在指定调律下的音程计算。
3. 实践操作：工作流、工具、状态、可编辑产物、质量指标。
4. 诊断与故障：可观察症状、候选原因、辨别方法、修正与停止。
5. 决策与对比：多种可行方案、条件、权衡、拒绝不适用方案。
6. 反例/边界：流派/语言/个体差异、越界推理、缺失证据、失败。
7. 真实案例：公开专业案例、授权工程或研究数据，核对来源、版本、条件与结果；不能将合成案例标为真实。
8. 跨域综合案例：从输入至交付和修改，贯穿 A01–A07；与单域教学案例不同。

## 案例记录候选契约
case_id、title、case_kind、evidence_status、domain/topic_ids、capability_ids、CQ_ids、scenario、objective、constraints、initial_state、inputs/artifact_refs、knowledge/claim_refs、workflow/decision_points、tool_capability_refs、alternatives、expected/observed outputs、evaluation criteria、failure/negative paths、revision/rollback/stop、source refs+locator、license/consent、limitations、review status。输入/输出需区分合成、预期、实际观测；允许不适用但说明原因；不得虚构真实音频、执行或听评。公开案例引用原文并遵守权利，不批量收集歌曲或个人录音。

## X03 案例结构示例（合成流程模板，无实际演唱结果）
- 知 A01：歌词音节与时值约束、风格/语言差异、歌声转换与合成适用性、许可条件，均须引用将来已接受主张；现在只列待查主题。
- 流 A02：确认许可与创作目标→获取可用乐谱/旋律和授权素材→分析音节/节拍→适配译词→选择真人演唱/SVS/SVC→对齐与混音→听评。许可不明则停止对应声音使用；多条方案可并存。
- 工 A03：歌声合成/转换、音高检测、乐谱编辑、音轨处理的能力描述；根据输入、语言、授权、版本和验证选择，不假定任何模型已支持缅甸语。
- 态 A04：原始旋律与素材（只读参考）→译词候选→对齐版本→人声候选→混音版本→待验收/需修改；修改歌词使相关对齐/歌声/混音证据失效，不应静默修改无关素材。
- 评 A05：语言语义、可唱性、旋律一致性、歌词发音、音质、审美及母语听评；阈值/条件待证，不自行生成“通过”分数。
- 编 A06：可编辑歌词、乐谱或 MIDI、独立人声与伴奏、工程记录、输出音频；WAV 不等同于可编辑全工程。保留明确版本和依赖。
- 循 A07：发现特定乐句错位→确认语言、节拍或生成原因→仅改目标译词/时值/演唱→重测受影响评价项→比较历史版本→保留或回滚；预算、停止与人工确认待制定。
- 负例：无授权参考、无法确定声调与旋律适配、模型不支持语种、分离伪影、错误对齐；返回限制或 UNKNOWN，不用 LLM 推测补齐。

## 建设和审核
L1 每 D2 主题分支至少登记适用案例类型、CQ 和候选案例，允许共享案例但要引用具体切片；缺少真实来源明确标记。L2 设计独立 Case 表达、关联知识/流程/状态/工具/评价/产物/循环、验证 fixture，试点同时含正例、反例、失败、跨域综合及证据缺失。P3 随知识分批产出案例，不能只在末期补写；真实案例须证据审核。P4 以案例重建、跨域 CQ、对照推理和负例验证作为验收，避免只计案例数。案例本身不授权真实工具执行、声音处理或发布。
