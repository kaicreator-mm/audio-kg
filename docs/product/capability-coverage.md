## 语义与责任边界
- P 对应实际主题/记录/案例和可查询路径，S 引用唯一 owner，C 依据实际专业任务说明；不是每个音程定义都必须附工具或工作流。L1 逐格校准；允许 N/A（有理由）、UNKNOWN（待证）和覆盖缺口；不得以空模板宣称覆盖。
- 业务流程记录不是 ADS 开发流程，领域状态不是 GitHub Issue 状态；音频编辑能力不是图谱本身能操作 DAW；领域经验循环不是图谱自动训练或自我进化的运行时。
- L2 决定表达方式；需要 Workflow/Step/Decision/State/Transition/ToolCapability/ArtifactSpec/EvaluationCriterion/Feedback/Revision/Case 等实体或等价表达及有条件关系。不能只用泛 related_to；状态、时序、依赖、因果、约束和版本分别表达；外部工具版本事实与稳定领域知识分离。
- A02–A07 与 A01 共用 Source/Claim/适用范围/审核机制；工具市场描述、合成案例和假设不能替代证据。

## 新增能力问题（接续 CQ01–18）
CQ19 如何根据创作/制作任务和输入状态选择一条可行流程，并说明依赖、替代、失败与停止条件？（A02）
CQ20 如何依据能力、版本、输入、许可、限制及验证证据选择工具或拒绝调用？（A03）
CQ21 一次编辑前后有哪些领域对象状态变化，何时应使依赖产物失效，如何保护原始素材？（A04）
CQ22 如何选择指标和人工听评，并避免把声学分数或审美偏好当作唯一质量真值？（A05）
CQ23 如何区分 WAV、stem、MIDI、乐谱与 DAW 工程可编辑能力及转换损失？（A06）
CQ24 如何在失败后定位原因、最小修正、复测、对照/回滚并保存证据，何时停止？（A07）
CQ25 如何从一个案例追溯各阶段相关知识、证据、输入输出、状态、选择依据及结果？（A01–07）
CQ26 不同流派/语言/教学对象/硬件约束如何改变可选流程和评价，并拒绝越界推理？（A01–07）

## 验收
L1：完成 D2×能力的适用性/覆盖规划，缺口与 owner 清楚，每个 P 至少可定位到知识需求、案例或 CQ；并核验全局七能力均有真实跨域用例。L2：为 A01–07 设计可检索表示和至少一条贯穿链，含失败/替代/回滚与证据约束（可用合成数据验证结构，不声称真实业务效果）。内容批次：P/S/C 按审核后的需求验证，输出覆盖矩阵及缺口；集成：使用案例查询重建过程并评估输出，拒绝无支持的推理，不要求部署或执行真实音乐工作流。独立审核 scope/contract/batches/candidate。
